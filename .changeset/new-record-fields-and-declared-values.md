**Breaking for anything that matches `: null` in a scaffold.** `urzua new` changes what it writes: a field it has no value for is now written empty (`Kind:`, nothing after the colon) instead of `Kind: null`, whether the field is required or optional, and the same fields are written in the same order as before. A script or check that looked for `: null` in a new record must look for an empty value instead (both read the same to every rule). The date, author and status are filled only in fields the type requires; a field only the template lists is written empty, as before. `new` never copies a template's text into a header field and never writes `—` for you. `new`'s output gains `to_fill`, one entry per empty field as `{field, required, hint, allowed, if_empty}`: `allowed` is the values the type declares for the field in `field_values`; `hint` is that list (`allowed: a, b`) when there is one, else the template's text for the field (for example `feature | bug | chore`), and never a dash or a built-in placeholder word such as `TBD` or `name(s)`; `if_empty` says what leaving the field empty means where the configuration decides it (a waiver's `Expires`, and the fields a `permanent` entry reads). The next action names required fields as required and optional ones as optional. `new`'s output also gains `status_from`, and `new` starts a record at the first of the type's declared `statuses.initial` instead of the first of `statuses.values` (this changes what `new` writes for a type whose first value is not its initial state); it falls back to the first value only when no `initial` is declared. `check` still reports an empty required field as empty, a required pointer field included. An empty optional pointer field (`Parent:`, `Parent: ""`, `Parent: null`, `Parent: ~`, or whitespace) is no longer reported by `header.pointer-field-clean`, which on 0.4.8 reported it as an unclean entry `""`. A present but empty `Expires` on a waiver, whether `Expires:` or `Expires: null`, still leaves the waiver without effect: it suppresses nothing and is reported as expired, now with a message saying the expiry is empty and must be filled or the line removed. Apart from the pointer false alarm going away, no finding on an existing record changes. A value a type declares for a field is no longer reported as a built-in placeholder or pending word in that field: a status named `Todo` in `statuses.values`, or a value listed in `field_values`, passes `field.quality` and `field.pending` there, while the same word in another field is still reported, and a value the type also lists in its own `statuses.placeholders` or `statuses.pending` is still reported, as the type asked. `urzua doctor` names such an overlap with the new `info` check status in `declared-value-vocabulary`, and warns, naming both configuration lines, when a type lists one of its own declared values (a status value or a `field_values` entry) under `statuses.placeholders` or `statuses.pending`.

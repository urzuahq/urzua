`urzua new` changes what it writes: a field it has no value for is now written empty (`Kind:`, nothing after the colon) instead of `Kind: null`, whether the field is required or optional, and the same fields are written in the same order as before. `new` never copies a template's text into a header field and never writes `—` for you. Its report gains `to_fill`, one entry per empty field as `{field, required, hint, allowed}`, where `allowed` is the values the type declares for that field in `field_values` and `hint` is that list (`allowed: a, b`) when there is one, else the template's text for the field (for example `name(s)` or `feature | bug | chore`), or `null`; a template value of `—` is never offered as a hint; the next action names those fields. `check` still reports an empty required field as empty. An empty optional field is reported by no rule: in particular `header.pointer-field-clean` no longer reports an empty optional pointer field as an unclean entry `""`. A present but empty `Expires` on a suppression record (waiver), whether `Expires:` as `new` now writes it or an older `Expires: null`, still leaves the record without effect: it suppresses nothing and is reported as expired, with a message saying the expiry is empty and must be filled or the line removed. An existing record's `Field: null` reads exactly as before; apart from that false alarm going away, no finding on an existing record changes. A value a type declares for a field is no longer reported as a placeholder or pending in that field: a status named `Todo` in `statuses.values`, or a value listed in `field_values`, passes `field.quality` and `field.pending` there, while the same word in another field is still reported. `urzua doctor` names such a value with the new `info` check status in `declared-value-vocabulary`, and reports at `warn` a type that lists one of its own declared values, a status value or a `field_values` entry, under `statuses.placeholders` or `statuses.pending`. `urzua new` also starts a record at the type's declared `statuses.initial` when the type declares one, instead of the first of `statuses.values`.

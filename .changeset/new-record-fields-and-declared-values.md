`urzua new` changes what it writes: a field it has no value for is now written empty (`Kind:`, nothing after the colon) instead of `Kind: null`, whether the field is required or optional, and the same fields are written in the same order as before. `new` never copies a template's text into a header field and never writes `—` for you. Its report gains `to_fill`, one entry per empty field as `{field, required, hint}`, where `hint` is the template's text for that field (for example `name(s)` or `feature | bug | chore`) or `null`; the next action names those fields. `check` still reports an empty required field as Blank. An empty optional field is reported by no rule: in particular `header.pointer-field-clean` no longer reports an empty optional pointer field as an unclean entry `""`, and an empty waiver `Expires` reads as no expiry rather than as an expired date. An existing record's `Field: null` reads exactly as before; apart from those two false alarms going away, no finding on an existing record changes. A value a type declares for a field is no longer reported as a placeholder or pending in that field: a status named `Todo` in `statuses.values`, or a value listed in `field_values`, passes `field.quality` and `field.pending` there, while the same word in another field is still reported. `urzua doctor` names such a value with the new `info` check status in `declared-value-vocabulary`, and reports at `warn` a type that lists its own declared status under `statuses.placeholders` or `statuses.pending`.

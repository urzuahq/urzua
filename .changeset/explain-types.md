`urzua explain --types` prints a short JSON summary of every record type the configuration declares: its prefix, directories, the `urzua new` command, required and optional fields, states with the initial ones, reference fields with the types they may name, and how many requirements it has, plus the rules on because of a declaration and the rules a declaration needs that are off. `urzua explain --type <name>` prints one type in full, and `urzua explain --types --full` every type in full together with the repository's other settings: field values, allowed moves in declared order, each `statuses.require` and `statuses.forbid` entry with its condition keys, one generated sentence and the pending values that count as missing, authority gates with who may act, and every other declared key under its own name. Every entry carries the key path and line it was read from; the four entries not read from the configuration (an undeclared initial state, a rule on by declaration, an undeclared prefix, the conventional template file) are marked `"default": true` with their `source`. An undeclared type name exits 2. On a healthy session start the harness tells the agent, and only the agent, to run `urzua explain --types`. For one type, the rules listed are every rule in effect that reads something the type takes part in, wherever it is declared, each naming the declarations that make it apply. A reference field reports its own targets, each relation pair's `target_types` and the effective result, `"any"` when nothing constrains it. Where a type declares no `statuses.initial`, the report says no starting status is required and names the status `urzua new` writes. `--full` goes with `--types` only.

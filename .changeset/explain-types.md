`urzua explain --types` prints a short JSON summary of every record type the configuration declares: its prefix, directories, the `urzua new` command, required and optional fields, states with the initial ones, reference fields with the types they may name, and how many requirements it has. `urzua explain --type <name>` prints one type in full, and `urzua explain --types --full` every type in full together with the repository's other settings: field values, allowed moves in declared order, each `statuses.require` and `statuses.forbid` entry with its condition keys, one generated sentence and the pending values that count as missing, authority gates with who may act, and every other declared key under its own name. Every entry carries the key path and line it was read from; the entries not read from the configuration (an undeclared initial state, the status `urzua new` writes, an undeclared prefix, the conventional template file, the built-in pending and placeholder lists) are marked `"default": true` with their `source`. An undeclared type name exits 2. On a healthy session start the harness tells the agent, and only the agent, to run `urzua explain --types`. A reference field reports its own targets, each relation pair's `target_types` and the effective result, `"any"` when nothing constrains it. Where a type declares no `statuses.initial`, the report says no starting status is required; `new_writes` shows the status `urzua new` writes, when it writes one. `--full` goes with `--types` only. `--types --full` lists the rules set in the configuration as written; the command does not say which rules apply to a type, which `urzua check` reports. A type `urzua new` refuses shows the refusal instead of a create command.

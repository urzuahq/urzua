# 220 — urzua installs the git hooks that doctor asks for

## What

Add a command that wires the pre-commit and pre-push hooks `urzua doctor` reports as missing, and ship a hook definition for the pre-commit framework.

## Why

the audit of 2026-11-15 found that `doctor` warns when git hooks are missing but no command installs them; this repository wires its own with a Makefile target an adopter does not have.

## Done means

- One command installs the pre-commit and pre-push hooks in a repository that has none, and `urzua doctor` then reports the hook checks as passing. — evidence: code:rust/crates/urzua-cli/src/commands/hooks.rs@sha256:fafb5dc53c4db637c176f457d85a276cad7f05fd5476e103b31390a2fa75a0e2, test:rust/crates/urzua-cli/tests/hooks_install_integration.rs#default_layout_gets_both_hooks_and_doctor_then_passes@sha256:c26231da38077512339dcad799d571a9bed53ce2fd33a246e1e2e80f1b8e5f25
- The command refuses to overwrite an existing hook or a `core.hooksPath` it did not set, and says how to call urzua from it.
- A repository using the pre-commit framework can add urzua with a documented stanza, checked by a test that runs it.
- The session-start warning about missing hooks names the command. — evidence: code:rust/crates/urzua-cli/src/commands/hooks.rs#file_wiring@sha256:cff8fc9117f609417b5d0c3d86c252a05c2750a74aab06438c10d8616f93018f, test:rust/crates/urzua-cli/tests/hooks_install_integration.rs#default_layout_gets_both_hooks_and_doctor_then_passes@sha256:c26231da38077512339dcad799d571a9bed53ce2fd33a246e1e2e80f1b8e5f25

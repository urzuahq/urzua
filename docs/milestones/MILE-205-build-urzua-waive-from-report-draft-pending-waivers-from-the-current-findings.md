# 205 — Build urzua waive --from-report: draft pending waivers from the current findings

## What

Build `urzua waive --from-report` of `ADR-91`: it drafts one waiver per rule and file for the current
unwaived findings, in the repository's waiver format, with a pending `Reason` and no `Expires` or
`Category`, dry-run unless `--apply`, filtered by `--rule` and `--path`, reporting as JSON what it wrote.

## Why

Phase 1 is where a real adopter's corpus exists and the tool is judged on getting that corpus to zero
findings (`MILE-102`, `MILE-118`). Adopting urzua on a second real corpus took 91 hand-written waivers. The
maintainer decided on 2026-11-05 that waivers stay the only suppression mechanism and there is no baseline
file, so adoption needs this command or it needs 91 transcriptions. It serves adoption, not the Phase 0
engine, so it belongs in Phase 1.

## Done means

- A suppression type may declare `statuses: {pending: [...]}` without `values`; a type declaring `values` loads as before. — evidence: test:rust/crates/urzua-core/src/status_model.rs#a_type_declaring_pending_and_no_values_loads_observed_failing, test:rust/crates/urzua-cli/tests/pending_only_statuses_integration.rs#a_pending_only_type_loads_and_check_runs
- Both the serde default (`status_model.rs:35`) and the empty-list check (`:368`) are relaxed, and a test fails before and passes after. — evidence: test:rust/crates/urzua-core/src/status_model.rs#a_type_declaring_pending_and_no_values_loads_observed_failing, test:rust/crates/urzua-core/src/status_model.rs#a_declaration_of_neither_values_nor_pending_is_refused
- Every reader of `values` is checked and covered: `decision_types` (`config.rs:1597`), `StatusDecl::declares`, `status_model.rs:263` and `:437`, `commands/new.rs:180`, `config.rs:2937` and `rules/status.rs:308`; any that breaks on an empty list is fixed. — evidence: test:rust/crates/urzua-core/src/status_model.rs#declares_is_false_for_every_status_when_no_values_are_declared, test:rust/crates/urzua-cli/tests/pending_only_statuses_integration.rs#new_leaves_the_status_blank_for_a_type_with_no_values, test:rust/crates/urzua-cli/tests/pending_only_statuses_integration.rs#decision_types_naming_a_status_of_a_type_with_no_values_is_refused_at_load
- `urzua waive --from-report` without `--apply` writes nothing, and prints JSON with `status`, `mode`, `pending_value`, `pending_source`, `drafts`, `skipped` and `unmatched_filters`. — evidence: test:rust/crates/urzua-cli/tests/waive_from_report_integration.rs#a_clean_corpus_drafts_nothing_and_still_exits_0, test:rust/crates/urzua-cli/tests/waive_from_report_integration.rs#two_files_and_three_rules_give_six_drafts_numbered_after_the_highest_waiver
- `urzua waive --from-report --apply` writes the drafts and each `drafts[].written` is true. — evidence: test:rust/crates/urzua-cli/tests/waive_apply_integration.rs#apply_writes_the_six_drafts_and_each_is_written_true
- Tests plant findings in two files and three rules and assert one draft per rule and file, numbered after the highest existing waiver and fitted to the declared identity. — evidence: test:rust/crates/urzua-cli/tests/waive_from_report_integration.rs#two_files_and_three_rules_give_six_drafts_numbered_after_the_highest_waiver
- A draft has `Reason` set to the type's first declared whole-value pending entry, else `Pending`, with `pending_source` saying which; `Expires`, `Category` and `Justified-by` are `null`. — evidence: test:rust/crates/urzua-cli/tests/waive_from_report_integration.rs#the_pending_value_is_the_declared_whole_value_else_pending, test:rust/crates/urzua-cli/tests/waive_apply_integration.rs#a_written_draft_has_a_pending_reason_no_expires_key_and_the_findings_as_its_body
- `urzua check` then reports the original finding again and `waiver-ineffective` on the draft, and exits 1 under `fail_on: warning`; after a real `Reason` and `Expires` are written the finding is waived. — evidence: test:rust/crates/urzua-cli/tests/waive_apply_integration.rs#check_after_apply_reports_the_original_findings_and_waiver_ineffective_and_exits_1, test:rust/crates/urzua-cli/tests/waive_apply_integration.rs#a_real_reason_and_expires_make_the_finding_waived
- On a type declaring `permanent`, a draft whose author fills only `Reason` is still ineffective (`RuleNotListed` or `CategoryMissing`), asserted by a test. — evidence: test:rust/crates/urzua-cli/tests/waive_apply_integration.rs#on_a_permanent_type_a_reason_alone_leaves_the_draft_ineffective
- The command exits 2 and writes nothing when `Reason` is not in `effective_requires`, when the chosen value classifies as `Present`, when `pending` holds only patterns, or when the type neither declares `permanent` nor lists `Expires` in `effective_requires`; the last message names the fix (declare `permanent`, or require `Expires`). Each is a test. — evidence: test:rust/crates/urzua-cli/tests/waive_from_report_integration.rs#it_refuses_when_reason_is_not_in_effective_requires, test:rust/crates/urzua-cli/tests/waive_from_report_integration.rs#it_refuses_when_pending_holds_only_patterns, test:rust/crates/urzua-cli/tests/waive_from_report_integration.rs#it_refuses_a_type_with_neither_permanent_nor_expires_required_and_names_both_fixes
- Findings of `waiver.matches-nothing`, findings with no file, and findings already named by a waiver with the same rule and scope are listed in `skipped` with a reason; a second `--apply` writes nothing. — evidence: test:rust/crates/urzua-cli/tests/waive_from_report_integration.rs#a_finding_a_waiver_already_names_is_skipped_with_that_waiver, test:rust/crates/urzua-cli/tests/waive_from_report_integration.rs#a_waiver_matches_nothing_finding_is_skipped_not_drafted, test:rust/crates/urzua-cli/tests/waive_apply_integration.rs#a_second_apply_writes_nothing
- Info findings are skipped and not listed in `skipped`. — evidence: test:rust/crates/urzua-cli/tests/waive_from_report_integration.rs#info_and_below_fail_on_findings_are_not_drafted_and_not_listed
- A finding that writing the drafts would itself resolve (judged on the tree with the drafts in memory, for example a waiver directory that matches nothing before the first waiver exists) is not drafted and is listed in `skipped` with that reason (`ADR-91` amendment of 2026-11-08); a test plants it. — evidence: test:rust/crates/urzua-cli/tests/waive_from_report_integration.rs#a_finding_the_drafts_themselves_resolve_is_skipped_and_listed, test:rust/crates/urzua-cli/tests/waive_apply_integration.rs#a_finding_reported_resolved_is_gone_after_apply, test:rust/crates/urzua-cli/tests/waive_apply_integration.rs#a_finding_resolved_only_by_its_own_draft_is_not_reported_as_resolved
- `--rule` with an unknown id exits 2. — evidence: test:rust/crates/urzua-cli/tests/waive_from_report_integration.rs#an_unknown_rule_exits_2_and_writes_nothing
- `--path` takes plain paths (a file or directory prefix, no glob), and a filter that matches nothing is in `unmatched_filters`. — evidence: test:rust/crates/urzua-cli/tests/waive_from_report_integration.rs#rule_and_path_filters_narrow_and_unmatched_filters_are_listed
- The scaffold is shared with `urzua new`, not duplicated; `new`'s tests are unchanged. — evidence: test:rust/crates/urzua-core/src/new_record.rs#scaffold_record_builds_header_and_template_body_from_a_synthetic_type
- The command is exercised in this repository: `urzua waive --from-report` on a scratch copy with a planted finding drafts a waiver, and `urzua check` and `check --base origin/main` show 0 unwaived findings on the merged tree.
- `SPEC-10`, `SPEC-3`, `SPEC-12` and a new spec describe the command; `make records` and `make rule-table-check` pass.

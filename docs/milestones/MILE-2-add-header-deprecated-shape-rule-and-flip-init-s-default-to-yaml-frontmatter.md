# 2 — Add header.deprecated-shape rule and flip init's default to yaml-frontmatter

## What

A non-blocking check-rule warning when a record type's configured shape isn't yaml-frontmatter, and init proposing yaml-frontmatter for any newly-adopted type.

## Why

ADR-33 decided the deprecation; this is the mechanism that actually makes it visible and steers new adoptions, without breaking anyone still on blockquote/bold-list.

## Done means

- `urzua init` in adopt mode proposes `header_shape: yaml-frontmatter` for every type it proposes, whatever shape the corpus's records were detected in. — evidence: code:rust/crates/urzua-cli/src/commands/init.rs@sha256:3b79d9cdc7698a0729345b5aca2d7c09878b4deb15260cb673f94692a17ef837, test:rust/crates/urzua-cli/tests/check_integration.rs#init_then_check_names_a_pre_existing_blockquote_record_as_an_unsupported_form@sha256:9b461195cbe65125a75fecc99787707b0f07b1eac93b3b86d57e0d859ff8f136
- `urzua init` warns that records not in that shape will be unreadable until rewritten. The non-blocking `header.deprecated-shape` rule this milestone also built was retired with the shapes it warned about by `MILE-85`, so what remains true is the `init` default. — evidence: code:rust/crates/urzua-cli/src/commands/init.rs@sha256:3b79d9cdc7698a0729345b5aca2d7c09878b4deb15260cb673f94692a17ef837, test:rust/crates/urzua-cli/tests/check_integration.rs#init_then_check_names_a_pre_existing_blockquote_record_as_an_unsupported_form@sha256:9b461195cbe65125a75fecc99787707b0f07b1eac93b3b86d57e0d859ff8f136

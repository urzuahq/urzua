# 365 — Not-run reports carry error_kinds, a usage error names its argument without the parser's usage block, and a panic reports under error

## What

`error_kinds` on every `not-run` report (`usage`, `config`, `environment` or `internal`, as the contract defines them); a usage error's `error` is one sentence naming the argument that was wrong, with no clap `Usage:` block; and the panic report's text moves from the `panic` key to `error`, with `error_kinds` `internal`.

## Why

Contract 1.1 (the published agent CLI contract's RFC-4) is taken whole: urzua prints `contract_version` `"1.1"` only when every piece below is delivered (`MILE-370`). Today `main.rs` passes `e.to_string()` of the argument parser to `refuse`, so the parser's prose and its `Usage:` block land in `error`; `CouldNotRun` (`urzua-core/src/report.rs`) has no kind; and `install_panic_hook` prints the text under `panic`. The contract treats `error` as text a reader never parses, and `error_kinds` as the data. This is the smallest, independent piece and the one every later piece's tests lean on. The addition-only rule of `MILE-359` holds: no existing key is renamed or removed, except the `panic` key, which `SPEC-1` documents and the contract replaces with `error`; `SPEC-1` changes with a revision row.

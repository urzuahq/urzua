# 1 — Fix urzua new's template-priority bug

## What

urzua new picks blockquote vs. YAML frontmatter by whether a template file exists, ignoring the configured header_shape entirely.

## Why

Flipping any type's header_shape to yaml-frontmatter without this fix means urzua new keeps emitting blockquote content that check can't parse under the declared shape -- silently broken output.

## Done means

- `urzua new` for a type configured `yaml-frontmatter` emits a YAML-frontmatter record whether or not a blockquote-shaped template file exists. — evidence: code:rust/crates/urzua-cli/src/commands/new.rs@sha256:8cb79491eccb0c34eba66c37899fc3cb0860427e67bd83a3fd6ee3e551bb8d4d, code:rust/crates/urzua-core/src/new_record.rs@sha256:4f85670917b92d9e09fca2a839bfb9e6035e439dd7bf8081b6b03849c496578d, test:rust/crates/urzua-cli/tests/new_integration.rs#new_emits_yaml_frontmatter_when_configured_even_with_a_blockquote_template_present@sha256:abbf083803b8a4fe62e6e7b933ffdec9e9964180b452f0a00334eaca302cfbd0
- A test plants a blockquote-shaped template and fails if the output is blockquote (`new_emits_yaml_frontmatter_when_configured_even_with_a_blockquote_template_present`). — evidence: test:rust/crates/urzua-cli/tests/new_integration.rs#new_emits_yaml_frontmatter_when_configured_even_with_a_blockquote_template_present@sha256:abbf083803b8a4fe62e6e7b933ffdec9e9964180b452f0a00334eaca302cfbd0
- The configured `header_shape` is the only thing that picks the output shape. — evidence: code:rust/crates/urzua-cli/src/commands/new.rs@sha256:8cb79491eccb0c34eba66c37899fc3cb0860427e67bd83a3fd6ee3e551bb8d4d

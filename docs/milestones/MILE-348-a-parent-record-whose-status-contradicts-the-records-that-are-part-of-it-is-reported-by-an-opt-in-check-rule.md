# 348 — A parent record whose status contradicts the records that are part of it is reported by an opt-in check rule

## What

An opt-in `check` rule, `status.children-agreement`, reports on a parent record's file when its status contradicts the records that are part of it (through the type's `pointer_fields` entry declared `part_of: true`): not started while a child is under way or finished, or finished while a child is neither finished nor dropped. It reads the same states `urzua export` computes, offers a suggested action for the first case where the configuration allows one, and is heard at edit time when a command or an edit changes a child.

## Why

An adopting repository reported on 2026-11-18, on 0.4.11, that over two days an agent moved 18 child records to an in-progress or finished status and never touched their parents. Nothing objected, so 12 parent records stayed at their initial status; `urzua check` has no rule about a record and the records that are part of it and nothing in the configuration could ask for one. The first thing that showed it was the board. That repository now runs a script over the export that fails on `state_disagrees_with_children`, and will delete it once a rule exists. The engine already computes the disagreement for the export (`MILE-330`); the rule makes `check`, the editor hook and the pull request see the same fact.
